META trace 2.2.0-rc.1 — sources and licensing
=============================================
The application processes selected files locally. All runtime libraries,
maps and styles are included in the HTML. No API keys or live tiles are used.

MAP RENDERERS
The 3D globe is a Canvas 2D perspective renderer written for this project (globe-math.js, globe-data.js,
globe-view.js, globe-director.js). It uses no third-party library and no WebGL. MapLibre GL JS, three.js and
CesiumJS were investigated and not used (docs/MAP_ARCHITECTURE.md, section 1, says why); none of them is bundled.

GLOBE BASEMAP (default 3D globe view)
Derived by tools/build_globe_pack.py into data/globe-pack.json (about 0.3 MB) from two inputs
already in this repository, with nothing added from any other source:
 - the Natural Earth 1:110m country polygons above (public domain). The coastline and the
   national borders are derived from them: an edge two country rings share is a border, an edge
   only one ring has is coast.
 - data/sources/zone.tab, the IANA time-zone table (public domain), which gives one reference
   city for each time-zone region. These cities are reference points, not a ranking of the
   largest cities, and the pack says so in its own metadata.
The input files are listed with SHA-256 digests inside the pack. 1:110m data is accurate to a few
kilometres; it is a world overview and carries no street or building detail.
Richer Natural Earth layers (1:50m, 1:10m, states, lakes, rivers, roads, railways, populated
places) can be rebuilt into the pack with the options of tools/build_globe_pack.py, or installed as
an optional regional package (see docs/MAP_DATA.md). None of that data was available where this work
was done, so none is bundled, and those options were not run: only the default inputs were (the
rebuild reproduces data/globe-pack.json byte for byte).

OPTIONAL MAP PACKAGES (nothing is bundled)
The app can read a regional map package the person chooses: one PMTiles v3 file of Mapbox Vector Tiles.
pmtiles-reader.js, mvt-decoder.js, tile-schema.js, region-manager.js and pack-store.js were written for this project
from the public format descriptions; no code from another project is included.
 - PMTiles: https://docs.protomaps.com/pmtiles/ and the version 3 specification at
   https://github.com/protomaps/PMTiles/blob/master/spec/v3/spec.md (tile-id test values from the specification are used
   in tests/pmtiles-reader.test.cjs).
 - Mapbox Vector Tile specification 2.1: https://github.com/mapbox/vector-tile-spec
 - Protomaps basemap layers and properties (roads, buildings, water, landuse, places, pois; kind, kind_detail, name):
   https://docs.protomaps.com/basemaps/layers ; planet-size figure and the `pmtiles extract` command:
   https://docs.protomaps.com/basemaps/downloads and https://docs.protomaps.com/pmtiles/cli
   (the Protomaps documentation was read on 2026-10-21 for these; the extract command was not run here).
 - The schema adapter was first written from that description and then checked against one real Protomaps basemap archive,
   the sample published in the PMTiles repository: https://github.com/protomaps/PMTiles, file
   spec/v3/protomaps(vector)ODbL_firenze.pmtiles, commit aec8fa1341222fdddb3318e9ffa8e18e19b312f7, read 2026-10-26,
   copied unchanged to data/samples/protomaps-basemap-firenze.pmtiles (SHA-256 recorded in data/samples/README.txt).
   Its tiles use property names prefixed "pmap:" (pmap:kind, pmap:kind_detail, pmap:min_zoom, pmap:level, pmap:link) and the
   layers physical_line, physical_point, transit and natural, which the description above does not list; tile-schema.js
   reads them from what was found in that file. Map data licence: ODbL 1.0, credit "(c) OpenStreetMap contributors"
   (the file's own metadata and the PMTiles project's annotation). Nothing else from the repository is used: the sample
   is data, and no code from it is included. The photograph tests/fixtures/gps-florence-duomo.jpg is generated by
   tests/generate_fixtures.py (a synthetic image carrying GPS tags for the Piazza del Duomo; it is not a photograph of anything).
 - OpenMapTiles layer names are read as well, on the same terms: https://openmaptiles.org/schema/
   (this page and the Mapbox specification link above were not re-fetched on 2026-10-21).
Licence and credit of any package belong to that package. The app shows the package's own "attribution" metadata in
the Map data dialog and under the map, and refuses nothing on licence grounds, because it cannot judge one. Protomaps
basemap builds are derived from OpenStreetMap (ODbL); the Protomaps documentation describes the project as released under
the BSD and ODbL licences without saying which covers which part, so check the terms of the build you download. tools/make_pmtiles.py
writes whatever attribution and licence note you pass it. Packages made from the bundled Gainesville data carry
"(c) OpenStreetMap contributors, ODbL 1.0".
Packages written by the tests (tests/helpers/test-package.cjs) are synthetic: a street grid laid over a place for
checking the loader. They say so in their metadata and the app flags them; they are not maps.

INTERFACE SOUNDS, FONTS AND ICONS
The interface sounds are generated while the app runs, from oscillators and filtered noise
(audio-engine.js). No recorded audio, sample, sound library or audio file is included.
No web fonts are included or requested; the interface uses the fonts already installed
on the computer (Segoe UI, Bahnschrift, system defaults). The icons and the browser-tab
mark are hand-drawn inline SVG made for this project. No third-party artwork is used.

DEVELOPMENT TOOLS (not part of the app, not needed to run it)
Playwright 1.56.1 (Apache-2.0) and its Chromium build, to run the browser tests.
Pillow, to regenerate the synthetic test images.
Neither is bundled. package.json names Playwright; there is no lockfile because the
package registry could not be reached where the work was done. Run npm install to create one.

VERIFICATION IMAGES
docs/verification contains screenshots taken by the browser tests of synthetic test

TEST IMAGES AND RESULTS
The tiny color images in tests/fixtures are synthetic, created by
tests/generate_fixtures.py with Pillow and deliberately chosen GPS values.
They are parser test inputs, not user photographs or location evidence.
Runtime coordinates come only from validated embedded metadata in the image
the user selects. No fixed example location is used when GPS is missing.
SHA-256 and analysis logs are calculated during analysis; no model, packet
capture, identity matching or visual geolocation system is included.
